# Cottage Bakery Site — repo map

Two independently-deployable services, split deliberately as a practice
exercise (see `docs/adr/0004-service-boundary.md` for the honest cost/
benefit accounting — this is over-engineering for the app's real scale,
kept for the skill-building value).

- `web/` — Next.js 16 frontend (BFF). Owns the UI, the cart, and admin
  session cookies. Never talks to Supabase directly; calls `api/` over
  HTTP. Has its own `web/CLAUDE.md` / `web/AGENTS.md` (Next.js-specific,
  the latter auto-regenerated by `next dev`).
- `api/` — Express + TypeScript backend. Owns Supabase (Postgres +
  Storage), business/legal order validation, and JWT-issuing admin auth.
  The only service that talks to the database.
- `specs/openapi.yaml` — the single source of truth for the web↔api HTTP
  contract. Both services generate TypeScript types from it
  (`npm run gen:types` in each) — never hand-edit the generated files.
- `specs/ENGINEERING_RULES.md` — cross-service conventions (money as
  cents, date-only handling, error envelope, auth header, testing bar,
  commit style). Read this before touching either service.
- `docs/` — architecture overview, testing strategy, and ADRs for the
  reasoning behind the above.

Run `docker compose up --build` from the root to run both services
together locally.
